# Public release gate — do not publish until approved

- [ ] Confirm authorized owner, institutional permission, logos and authorship.
- [ ] Review every screenshot at full resolution; replace any case-specific/confidential image.
- [ ] Confirm README scientific descriptions against final tested release.
- [ ] Approve proprietary distribution terms and user-facing privacy/licensing statements.
- [ ] Review all files for private keys, credentials, account DBs, research datasets and identifying metadata.
- [ ] Create a **new** public repository with fresh history; do not change visibility of the private source repository.
- [ ] Confirm no Python source, build cache, frozen application binaries or private Git history enter this documentation repository.
- [ ] Approve and add real authors, ORCIDs, institutional publisher and repository URL to `CITATION.cff`.
- [ ] Complete packaged-app tests, installer build, version-specific installation, uninstall, license and clean-machine QA.
- [ ] Obtain institutional security/distribution clearance; publish installer and SHA-256 under a GitHub Release only after approval.
- [ ] Enable Zenodo GitHub integration, archive approved release, verify DOI and update citation metadata.
- [ ] Preserve V1 and all previous release artifacts unchanged.
